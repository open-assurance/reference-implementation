# Roadmap

Concrete work is tracked in [issues](https://github.com/open-assurance/reference-implementation/issues); this page
says what matters and in which order.

## Near term

- **Human review of the generated code**, area by area (scoring fold, project model, each lens's detectors, outputs).
  The engine was generated by an AI model and has not yet had broad human review.
- **Close the not-measured dimensions** in [COVERAGE.md](COVERAGE.md) (37 of 165): the advisory judgment dimensions
  (D19–D22, D24, D25, M4, DM8, ED5, ES3, LA1–LA6), the runtime metas (AX*1) and D8 coverage — deterministic and offline by
  default, anything else opt-in and advisory. Also the benchmark concepts with no detector yet (mass assignment, NoSQL
  injection, subresource integrity, token-payload data, release cooldown).
- **Take part in the first CAI engine qualification window** under the same rules as every other engine, and publish
  the result here, whatever it is.

## Next

- **A second language.** TypeScript/JavaScript is the natural candidate (the catalog already defines the `R*` family and
  the benchmark has TypeScript units); Java is the other.
- **A second, independent implementation by others is welcome** — in another language or architecture, built from the
  published text. Two engines that agree from the same text are stronger evidence for the standard than one; where they
  disagree, SPEC-GAPS.md gets a new entry.

## Longer term

- **Maintainers from several organisations**, with no single organisation holding a majority (see
  [GOVERNANCE.md](GOVERNANCE.md)).
- Releases with versioned, reproducible binaries, and tracking each new rubric version as it is published.
